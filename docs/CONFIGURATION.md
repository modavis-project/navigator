# Configuration and data boundaries

The public WSGI entry point is `navigator_app:create_app()`. It accepts the existing
`pod-1.5-public` profile name, including the POD 1.6 projection. It rejects the
restricted `full` profile. There are no contribution, account-administration,
processing, internal-documentation or publication routes in this application.
The profile name is an interface identifier, not the installed dataset version.

For the standalone demonstration, use `scripts/fixture.py`; it isolates environment
settings, creates random temporary credentials, loads only the pinned synthetic
fixture and removes its own container. No configuration file is needed.

For an existing, explicitly selected public POD installation, use the reviewed
settings in `compose.yaml`, or supply equivalent process environment variables.
The application does not read `.env` itself; Docker Compose reads the private
file generated by `scripts/prepare.py`. Never include that file in a source archive.

| Setting | Meaning |
| --- | --- |
| `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | All required; no saved/default endpoint or usable password. Use a SELECT-only role. |
| `DB_PORT` | PostgreSQL port; default 5432. |
| `NAVIGATOR_DB_POOL_MAX_SIZE` | Maximum pooled connections per database and worker. Default 8. Use 1–8 to fit shared server capacity. |
| `NAVIGATOR_PUBLIC_DATABASE_MANIFEST` | Exact verified manifest for the selected public projection. |
| `NAVIGATOR_IDENTIFIER_LEDGER_PATH`, `NAVIGATOR_IDENTIFIER_LEDGER_SHA256` | Immutable identifier ledger and its SHA-256. POD 1.6 requires its retained ledger; a synthetic replacement is rejected. |
| `NAVIGATOR_PUBLIC_SOURCE_RELEASE_VERSION`, `NAVIGATOR_URI_RELEASE_VERSION` | Explicit dataset/source version; independent of application version. |
| `NAVIGATOR_URI_POLICY_VERSION`, `NAVIGATOR_URI_PUBLICATION_STATE` | Existing URI policy and actual publication state. The fixture uses policy 2 and `prepared`. |
| `NAVIGATOR_PUBLIC_BASE_URL`, `NAVIGATOR_RESOLVER_BASE_URL`, `NAVIGATOR_LINKED_DATA_BASE_URL` | Delivery origins for this installation. These do not create canonical identities. |
| `NAVIGATOR_CANONICAL_ID_BASE` | Canonical authority of the input release. The fixture must use its reserved `example.invalid` authority. |
| `NAVIGATOR_DATASET_DISTRIBUTION_MANIFEST`, `NAVIGATOR_DATASET_DISTRIBUTION_ORGAN_ROOT`, `NAVIGATOR_DATASET_DISTRIBUTION_ENTITY_ROOT` | Verified optional complete semantic archives. Entity exports remain separately capability-gated. |
| `NAVIGATOR_RESEARCH_INDEX`, `NAVIGATOR_WORKBENCH_MANIFEST`, `NAVIGATOR_EXPLORATION_MANIFEST`, `NAVIGATOR_OMARO_MANIFEST` | Optional, separately verified research/reference inputs; absent capabilities stay unavailable. |
| `NAVIGATOR_BACKEND_URL` | Development-only Vite proxy target. The browser receives public API responses, not database credentials. |

The Compose file explicitly selects all POD 1.6 bindings and mounts artifacts
read-only. It publishes only a loopback web port. Readiness at `/api/health/ready`
checks the configured database and release inputs; `/api/health/live` only proves
that the HTTP process is running. Do not treat a liveness response as data readiness.
The web image probes readiness through its own Nginx `/api/` proxy, so a healthy
static page alone cannot hide a disconnected backend. Docker reports probe
failures as unhealthy; this does not restart containers or notify an operator.
Configure external monitoring of this endpoint for the installation.
Nginx uses Docker DNS with a five-second cache to refresh the backend address. This
allows backend recreation or temporary DNS failure to recover without a web
reload. The configuration requires Nginx 1.27.3 or newer; the image pins 1.28.
Outside a Docker network, supply the installation's trusted DNS resolver instead
of Docker's `127.0.0.11`.
Instance discovery responses use `Cache-Control: no-store`, so a normal reload
can discover changed capabilities. Versioned entity representations retain ETags.

The retained settings structure contains optional compatibility fields for older
MODAVIS integrations. Private checkpoint and virtual-catalog paths have no implicit
local fallback. Setting an optional field does not activate a missing administrative
route. The standalone runtime requires no sibling repository or private contract file.

## Evidence rules

Preserve each source account, original wording, attribution and capture provenance.
Conflicting stop totals remain independent; a count of captured component rows is
not a source-reported total. Unknown dates or quantities stay unknown. Approximate
periods retain their expressions and precision instead of receiving invented exact
dates. Equal actor names do not establish identity. Source-only events remain
source claims, and missing stoplists cannot produce invented physical components.

These rules apply equally to page summaries, details, citations and semantic
exports. Synthetic examples are visibly labelled, use reserved URLs and cannot
claim a published POD identity. Restricted raw prose, media and processing queues
are outside the public profile. Optional research assets have their own manifests
and must not be substituted with unrelated local files.

## Recovery

Keep the selected source commit, package/resource manifests, original inputs and
private runtime configuration. A failed full-POD restore requires inspection and
a new independently named Compose project/volume for retry; initialization scripts
do not automatically repair a nonempty volume. Never remove a previous volume or
accepted input to make a new run pass. The synthetic route is disposable and can
be repeated from its manifest; stop only its receipt-named container.
